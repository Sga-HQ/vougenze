## 3. Invariant Governance & Enforcement Classification Map

To ensure accurate auditing, every project invariant is classified into one of four governance tiers, using exact schema vocabulary:

### Tier 1: Schema-Enforced (Pure SQLite Engine)
- Foreign key cascading and rejection (`PRAGMA foreign_keys = ON;`).
- Numerical attribute range checks (`like_rating BETWEEN 1 AND 10`, `formality BETWEEN 1 AND 5`, `wears_since_confirmed_wash >= 0`).
- State enumerations (`condition_state`, `availability_state`, `status`).
- Terminal laundry outcome consistency (`RETURNED_CLEAN` requires `wash_confirmed = 1`, `RETURNED_UNWASHED` requires `wash_confirmed = 0`).
- Partial unique indexes preventing double-active wear events per session (`idx_one_active_wear_event_per_session_garment`).
- Partial unique indexes preventing double-active outfit wear logs (`idx_one_active_wear_log_per_session`).
- Single-wear-event authorization consumption partial unique index (`idx_one_consumed_authorization_per_wear`).
- Unique authorization reservation index (`PlanWearAuthorizationReservation.authorization_id`).
- Date range ordering constraints (`effective_until >= effective_from`, `expected_return_date >= sent_date`, `horizon_end_date >= horizon_start_date`).

### Tier 2: Service-Enforced (Closed Mutation Boundary)
- Multi-write transaction ownership requirements (`_require_transaction()`).
- Cross-entity ownership validation (verifying User owns Session, Garments, Policies, and Batches).
- Wear preflight validation (garment availability, clean/reusable condition, role coverage, hard limit authorization).
- Laundry dispatch preflight (verifies `expected_return_date >= sent_date`, user ownership of batch and garments, policy existence and ownership if policy_id supplied, garments not already in laundry or retired, and garments have no active batch linkage `current_laundry_batch_id IS NULL`).
- Preference evidence atomicity and alternative inclusion validation:
  - Valid inclusion types: `PRESENTED`, `FEASIBLE_NOT_PRESENTED`, `INFEASIBLE_REFERENCE` (Note: `CONSIDERED` is not a valid schema value).
- Candidate intake statuses (`GarmentDuplicateCandidate.status`): `PENDING`, `SAME_GARMENT`, `DIFFERENT_GARMENT`, `LINKED_SIMILAR`, `DISMISSED`.
- Intake draft statuses (`GarmentIntakeDraft.status`): `PENDING`, `ATTACHED_TO_EXISTING`, `CREATED_NEW_GARMENT`, `CANCELLED`.
- Preference evidence service APIs: `record_selection_evidence`, `record_rejection_evidence`, `record_skipped_evidence`.
- Plan invalidation and authorization reservation release upon plan supersession or garment retirement.

### Tier 3: Audit-Detected (Mechanical Verification Probes)
- Orphan file detection on rollback (`test_88_duplicate_candidate_failure_rolls_back_everything`).
- Applied migration hash tamper detection (`test_95_migration_hash_tampering_fails_closed`).
- Schema invariant test result verification via `_schema_test_results` assertions in Python (`tests/test_db.py`).
- Domain consistency checks in simulator (`PRAGMA integrity_check`, orphaned batch reference queries).

### Tier 4: Currently Unenforced (Documented Gaps / V0 Non-Goals)
- Pure SQL-level JSON syntax validation (`CHECK (json_valid(...))`).
- Pure SQL-level ISO 8601 regex pattern enforcement on timestamp columns.
- Composite foreign keys enforcing cross-entity user matching.
- Crash-atomic file system / database two-phase commit.
